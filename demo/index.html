WebMCP Local Agent · playground

Two pages that expose WebMCP tools, for trying the extension without hunting for a site that implements the API.

Because these are served over HTTPS from a real origin, they also exercise the origin-matching path that a local file:// page cannot.

A createFeature tool with four required inputs and two constrained by enum / anyOf. Ask the agent to file a feature and watch it pick the declared constants.

A todo list with four tools. Try "add buy bread", "what is still pending?", "mark #1 as done", "switch the page to dark mode".

Setup

  1. Install the extension: grab the zip from the latest release, unzip it, then chrome://extensions → Developer mode → Load unpacked.
  2. Have Ollama running with a model that supports tools: 
    ollama pull qwen3:8b
  3. Let Ollama accept the extension's origin, then restart it from the tray icon: 
    setx OLLAMA_ORIGINS "chrome-extension://*"
  4. Open a demo above and click the extension icon.
Step 3 is not optional. Without it the model list loads fine but sending a message returns 403: chrome-extension:// is not in Ollama's default allowed origins. On Linux or macOS export OLLAMA_ORIGINS before ollama serve.
Reload the page (F5) after installing or reloading the extension. Content scripts are not injected into tabs that were already open.

What to look for

  • ● A green count on the toolbar icon as soon as a demo loads — no need to open the panel.
  • Tools — one card per tool, with its parameters and, where the schema declares them, the allowed values.
  • Execute — run a tool by hand through a form built from its schema, with a live JSON editor.
  • Chat — the model calls the tools itself; every call shows its arguments and result.
  • History — every run, manual or model-driven.
